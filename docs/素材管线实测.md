## 2. 裁切框（6 段共用）

切换动作时人物不能跳位，所以 6 段必须用**同一个**裁切框：

```
全 6 段所有帧的 alpha 并集 = x∈[286,996]、y∈[0,719]
取整并留余量 → CROP = (280, 0, 1003, 720)   原图 723×720
输出高度 512 → 宽度 round(723 × 512/720) = 514
```

输出 **514×512（宽高比 1.0039）**。

> ⚠️ 改裁切框会连带改 `runtime/electron-helper/renderer.js` 顶部的命中框比例常量，
> 两处必须一起改。

`idle` 的人物在该框内的相对位置（实心 `alpha>200` 口径，桌面窗命中判定用）：

| left | top | width | height |
| --- | --- | --- | --- |
| 0.2237 | 0.0332 | 0.5603 | 0.9414 |

## 3. alpha 管线：四代实现与实测数据

这条管线改了三轮才把边缘做干净。**每一步的差值都是量出来的**，不是"看着差不多"：

| 版本 | 做法 | 边缘反预乘亮度 | 问题 |
| --- | --- | --- | --- |
| v1 | 二值 mask + 高斯羽化 | **0.2** / 255 | 羽化带的 RGB 还是黑底 → 一圈脏黑边 |
| v2 | 3px 邻域**均值**扩散 | **0.6** | 均值被黑底稀释，几乎没改善 |
| v3-错误 | `distanceTransformWithLabels` 求最近邻 | **24.7** | 该 API 的标签语义与直觉相反，取色错位成黑 |
| **v4（采用）** | `scipy.distance_transform_edt` 最近邻**复制** | **101.9 ~ 116.6** | ✅ 与内部亮度 175 的差距属正常抗锯齿 |

**关键诊断方法**：打印一条穿过人物边缘的水平扫描线，逐像素看 `alpha / 原始RGB / 外扩后RGB`。
v3-错误版里连 `alpha=255` 的实心像素 RGB 都是 0 —— 这个现象直接证明"取色映射全错"，
而不是"扩散不够"。换成 v4 后同一位置变成 `a=228 → RGB[59,70,85]`（人物自己的颜色）。

### 一个 API 陷阱（记下来避免再踩）

`cv2.distanceTransformWithLabels(..., labelType=cv2.DIST_LABEL_PIXEL)` **不是**
"每个源点一个编号"。实测 6×6 图、2 个源点，返回的 labels 是 `1..34`（逐像素编号），
按直觉建映射表必然取错色。

## 4. 颜色通道（最隐蔽的 bug）

v3 曾经把 BGR 数据按原顺序塞进标记为 RGBA 的编码管道，结果是：

```
源图红围裙   BGR = [94, 93, 218]      → R=218（红）
v3 错误成品  BGRA = [219, 90, 95]     → B=219（红跑到蓝通道）
v4 修复后    RGBA = [218, 93, 94]     → R=218 ✅
```

**为什么差点放过**：alpha、尺寸、覆盖率、四角透明度全部正常，只有颜色反了。
肉眼看到的是"红围裙变紫、棕发变蓝"，很容易误判成"素材本身配色不对"。

**防守手段**：`scripts/check-assets.py` 里加了"红度"回归检查 ——
`人物区域的 mean(R) - mean(B)`，原片约 `+41~+51`，一旦 R/B 互换就翻成 `-41~-51`。
用旧的问题素材做过负向测试，能稳定报错并退出码 1。

## 6. 浏览器侧的两个坑（不是素材问题，但会导致"换了素材看不到变化"）

1. **长缓存**：`/asset/*` 带 `cache-control: public, max-age=86400`（素材是静态的，合理）。
   代价是改完素材后浏览器 24 小时内仍用旧文件。
   解法：桌面窗的素材 URL 统一带 `?v=<ASSET_VERSION>`（`runtime/electron-helper/renderer.js`），换素材时把这个号 +1。
2. **桌面窗在内存里**：Electron helper 启动时就把 `idle.webm` 读进 `<video>`，
   直接覆盖磁盘文件不会让它重新加载 —— 要么切换一次状态，要么重启 DSH。

## 7. 如果换成自己的角色

1. 6 段黑底 mp4 按 `待机 / 颠锅 / 上菜 / 托腮 / wink / 转圈` 命名放进 `assets/cook-已抠图/`；
2. `npm run assets`；
3. `npm run assets:check` —— 重点看"四角 alpha"、"暗部 alpha"、"红度（原片/成品）"三列；
4. 若裁切框变化，同步改 `runtime/electron-helper/renderer.js` 顶部的命中框比例；
5. 把 `runtime/electron-helper/renderer.js` 的 `ASSET_VERSION` +1。

> 更好的源头：如果能导出**带 alpha 的源视频**（ProRes 4444 `.mov` 或 PNG 序列），
> 就完全不需要"从黑底反推 alpha"这一整套推断，边缘会是原始渲染的真实结果。
